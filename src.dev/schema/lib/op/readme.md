- A schema is attached on `swrite` and any `set` operation; it describes the chunks so any exported container can be read by another host without explicit host-specific support.
- Each schema always has a local ID—either canonical or generated to match a known host configuration (TODO: generate on save — matt).
- Standards start from the library container, and hosts are welcome to generalize them for more efficient conversion.
- All paths within a schema are canonical.
- All data paths within a container are dotpaths. The schema can be embedded or derived from a `std` buffer, as long as the `optype` and identifiers match to trigger a lookup.
- All schema data is strict: no binary or human-readable definition may contain syntax errors (`-DDiagnoseSchema`).
